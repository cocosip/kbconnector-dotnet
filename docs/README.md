# KingbaseConnector Documentation

Baseline date: 2026-11-23. Last updated: 2026-11-26. The repository implements bounded four-mode public PG-wire text execution and ordinary direct/private pooling. E54-E56 add native/wide/PG-bit scalars plus mode-specific temporal/YEAR text paths and lossless MySQL provider calendars. E57 adds notification events/resumable Wait, E58 structured notices, E59 streaming text/raw binary COPY, E60 transaction-bound OID manager/streams with savepoint and pooled descriptor ownership, E61 ordinary LOB values, E62 network SequentialAccess/lazy batches, E63 buffered text COPY lifetime checks, E64 bounded Stream/TextReader parameter input, E65 typed binary COPY core, E66 exact numeric/PG temporal COPY, E67 JSON/PG bit COPY, E68 XML COPY with Unicode declaration normalization and E69 catalog/identifier scalar types. These increments have scoped four-mode LIVE and five exact-asset evidence; remaining binary COPY codecs/field streaming, enum/SET and array types, strong streaming KeyInfo and complete B05 acceptance remain open. Remaining temporal/complex families, schema/key metadata and DataAdapter/PG CommandBuilder with sequential adapter batching retain their stated acceptance scope. Five-target core/DI packages, preparation, buffered Readers and explicit transaction/batch foundations have the evidence recorded in the single progress tracker. It separates delivered subfeatures, database-mode/backend coverage and remaining acceptance. Its 122 parent-requirement closure counts are not a development percentage or a test count. Bounded four-mode LIVE does not establish complete mode/version/platform acceptance. Real-server TLS acceptance is temporarily deferred at the user's request because the supplied endpoints do not support TLS; offline TLS tests remain required.

PG remains the default connection protocol in all compatibility modes. Its ordinary execution and built-in pooling are implemented within the tracker boundaries. The explicit MySQL backend and its protocol-isolated pool remain designed contracts for exceptional installations exposing only MySQL protocol. WireProtocol selects the backend; CompatibilityMode selects database semantics.

All maintained project documentation is written in English. Keep temporary walkthroughs, review reports, and decompiled source outside the repository. Retain durable technical facts and source references in the design, matrix, or inventory where they belong.

The inventory is research evidence. It does not participate in runtime version detection or establish working server compatibility. Keep official static evidence, implementation progress, simulated validation, and live server acceptance separate. Source references also include the Kingbase MySQL-compatible C010 release declaration of MySQL protocol; endpoint-specific acceptance remains pending. Proposed API names and defaults remain identified as proposals until settled during the corresponding development task.
