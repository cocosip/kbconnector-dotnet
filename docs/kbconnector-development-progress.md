# KingbaseConnector Development Progress

Last updated: 2026-11-25. This is the single current implementation and acceptance tracker. Requirements are defined in the [feature matrix](kbconnector-feature-matrix.md); implementation workflow and completion rules are in the [development guide](kbconnector-development.md).

## 1. Current snapshot

DP01 engineering is implemented. DP03 implements the first configuration slice, offline server-requested PG password/MD5 authentication, bounded startup and TCP/platform TLS; DP04 adds bounded PG framing/control/error primitives and an owned internal Simple/Extended text-query session. DP02/DP03 add a documented candidate version query, bounded full-version parsing and an offline identity/mode probe; DP05 adds a bounded required-built-in catalog loader using actual OIDs, initial scalar text codecs and exact Decimal/KingbaseNumeric values. DP06 adds single-statement PG named/native parameter planning with confirmed lexical state, public input parameters/collections, catalog-bound snapshots with exact constraints and an internally constructed buffered KingbaseDataReader with basic schema. An internal physical owner now composes initialization stages with one deadline, literal startup settings and failure cleanup against loopback peers. Explicit package consumers run on Windows x64 .NET 8/9/10. E17 composes public unpooled PG Connection/Command/factory execution, safe server exceptions, Reader ownership and bounded CommandBehavior with the existing initializer and catalog-bound values. E29 adds bounded four-mode bootstrap and PG public execution LIVE evidence; cancellation-channel synchronization, full pooling acceptance, complete transaction coverage, remaining catalog/runtime formats and broader server acceptance remain open. E18 adds immutable unpooled DataSource ownership and the separate KingbaseConnector.DependencyInjection deliverable, including transient connections, singleton/keyed sources and verified per-TFM dependency floors. E19 adds the first ReadCommitted local transaction owner, commit certainty and bounded cleanup. E20 adds typed/BCL PG savepoints, server-derived identifier limits and failed-transaction rollback-to recovery. E21 adds exact ReadCommitted/RepeatableRead/Serializable requests and transaction-scoped read-only/read-write overloads, without live isolation acceptance. E22 adds Windows/Linux CI configuration, tag/config/nuspec version gates, exact-package provenance, release notes and tag-only trusted-publishing automation; hosted execution and publication are not yet accepted. E23 adds the internal opt-in PG physical reset foundation. E24 integrates ordinary public PG pooling, private/direct identities, bounded FIFO capacity, reset-before-reuse, generation clearing and lifetime/owner disposal; actual resource cleanup, system transactions and other backends remain pending. E25 adds standard SCRAM-SHA-256 login and Unicode 3.2 password preparation, with real Kingbase authentication still unaccepted. E26 adds owner-scoped password providers, bounded credential retrieval and rotation on physical creation; passfile/environment and live acceptance remain pending. Development resumed on 2026-11-25 after the E26 shutdown checkpoint. E27 implements configured CA trust and positive/negative TLS verification; real-server and additional-platform acceptance remain pending. All completed development commits are now on master; subsequent development and local commits use master directly as requested.

E28's internal named PG prepared-statement module was committed on master at a129a57 before shutdown. On 2026-11-25 the user supplied authorized private V9 environments and requested testing. E29 adds the first bounded live bootstrap/PG cases and fixes observed namespace/version assumptions. E30 integrates public synchronous/asynchronous Prepare/Unprepare and named execution, with five exact-asset probes and bounded real PG schema/transaction recovery. E31 adds opt-in bounded automatic PG preparation, threshold/reset/error lifecycle tests and five exact-asset probes. E32 adds the first PG DATE input/result slice with lossless KingbaseDate values, ISO format snapshots and modern DateOnly access. Deployment identities, credentials and raw records stay outside the repository. Batch APIs and remaining DP11 mode/platform acceptance remain open.

## 4. Feature ledger

Each matrix feature has exactly one row below. The matrix owns names, scope, and acceptance requirements; keep IDs synchronized when it changes. `[ ]` is open and `[x]` means **Complete** under development guide section 6. Use Not started, In progress, Implemented, Blocked, Complete, Deferred, or Not applicable for Status. Record an accepted profile/subset and evidence before checking a row.

SIM and LIVE are independent: Not run, Passed, Failed, or N/A with an explicit reason. A LIVE pass must name profiles in the evidence entry. N/A is not available merely because a server or test is missing. Deferred rows remain unchecked.
